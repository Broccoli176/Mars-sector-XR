Quick reminders if you only have this file:

- **Project:** stationary VR survival/management game in a first human Martian outpost (underground basement). **Meta Quest 3** primary, Three.js + Vite + WebXR + mitt, JavaScript + JSDoc/`@ts-check`, Vitest, Node 22. Player-facing text in **Spanish or English** (chosen in the start menu; tables in `src/data/strings/es|en/`); code/docs in English. Built in a **2-day hackathon, 14–15 Nov 2026**.
- **Current state:** prototype v0.1. Headless sim in `src/systems/` (Simulation composes Time, Resources, PowerGrid, SolarTracker, LifeSupport, Food, Kitchen, Crew, IncidentRunner, Telecom, Comms, Electronics, Rover, Radiation, GameState), data in `src/data/`, Vitest tests in `tests/`, greybox WebXR presentation (`src/core/main.js`, `world/`, `ui/`, `objects/`, `vr/`). Pending systems are listed in `AGENTS.md` §0.
- **Simulation boundaries (target):** simulation/systems logic headless (no rendering dependencies) and owning resource state through a single authority (e.g. `ResourceManager`). Presentation emits intents and reacts to events; do not mutate simulation state from render/interaction code.
- **MVP (target):** survive 7 accelerated in-game days (days start at 06:00; run ends day 8 06:00, ≈42 min at 1×); lose on health 0 (suffocation/hypothermia/dehydration/starvation), total power loss, or unrecoverable cascade (cascade is planned, not implemented). Phases `boot → training → playing → over | won`; pause = speed 0; auto-pause on headset removal. Layout: hub-and-spokes around the Sala central · Herramientas (hub). North: Telecom and Control room. West: Personal (crew quarters, dosimeter, radiation shelter). South: Hydro and Energy & O₂ (breakers + life support). See `docs/FLOOR_PLAN.md`. Spawn in Control. Tutorial = training bench in the hub. Space weather: a solar particle event from a real MSL RAD record is implemented; CME + radio blackouts from a static NASA DONKI snapshot are still pending.
- **VR/UX (target):** controllers first, teleport default (smooth optional with vignette), direct grab for physical controls, 2 hip holsters, **no head-locked HUD** except the team-approved alert banner (`src/ui/AlertBanner.js`: faults and pending jobs with their room) (diegetic panels/gauges/biomonitor). All panel and button text uses the shared theme in `src/ui/theme.js`. Desktop = Immersive Web Emulator only (dev tooling).
- **Perf budget (Quest 3, conservative Quest 2-class):** 72 Hz (60 floor), <150 draw calls (≈25 per room; measured ≤ 71 per view with room visibility culling `src/world/Visibility.js`, baked shell lighting `src/world/bakedLight.js` and 1-draw-call buttons — keep those patterns, `AGENTS.md` §7), 500k–1M tris, optimized textures, baked/static lighting favored, no post-processing chain by default.
- **Commands:** `npm ci`, `npm run dev|build|preview`, `npm test`, `npm run sim` (headless balance report). Start menu: «Realidad virtual» (Quest / Meta Immersive Web Emulator, or built-in IWER) or «Navegador» (`src/ui/StartMenu.js`). Dev URL params `?mode=browser` (skip menu), `?view=x,z,deg`, `?ff=ticks`, `?iwer` (emulated Quest 3 without extension), `?debug`, `?nocull` (draw every room, to compare). Keyboard dev locomotion (WASD + Q/E) works on desktop and inside emulated XR. Use the user camera (child of the rig) for head pose, not `renderer.xr.getCamera()`. Pending: `typecheck`, CI (GitHub Actions + Pages).
- **Team split (read first):** `docs/COLLABORATION.md`. Person A owns Personal, Hydro and Hub; person B owns Telecom, Control and Energy. Each room is `src/rooms/<room>/stations.js` + `src/data/{stations,strings/es,balance}/<file>.json`. Shared files only change through small announced PRs. Work on short branches from `main`. Never commit or push without the user's explicit authorization.
- **Key docs:** `docs/AGENT_CONTEXT.md` (design), `docs/SIMULATION_SPEC.md` (numeric/spec baseline + data schemas), `docs/CONTENT_SCRIPT.md` (comms/tutorial/string keys), `docs/FLOOR_PLAN.md` (layout), `docs/DEVELOPMENT_WORKFLOW.md` (incl. hackathon plan), `docs/ASSET_CREATION_WORKFLOW.md`, `docs/references/registro_nasa_donki.md`, `docs/project-context.json`.

When contracts (events, save schema, layout, budgets) are defined or changed, update `AGENTS.md` and related docs in the same change. Keep specs, data schemas, and tests consistent once implementation begins.
